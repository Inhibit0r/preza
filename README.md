# preza

Презентации в редактируемом PowerPoint для Codex и Claude Code. Начальная сессия ведёт работу, независимое ревью делает свежий субагент той же среды, изображения создаёт Codex `$imagegen`. [PPT Master](https://github.com/hugohe3/ppt-master) собирает SVG в нативный PPTX. Речь в Word и анимация добавляются по запросу.

## Быстрый старт

Codex:

```sh
codex plugin marketplace add Inhibit0r/preza
codex plugin add preza@preza
```

Начните новую сессию, вызовите `$preza:setup`, затем `$preza:preza` с задачей.

Marketplace использует файлы своего выбранного checkout: `codex plugin marketplace add Inhibit0r/preza --ref <ветка-или-тег>` сохраняет выбранную версию и не переадресует установку плагина обратно на `main`.

Claude Code:

```sh
claude plugin marketplace add Inhibit0r/preza
claude plugin install preza@preza
claude plugin install ppt-master@preza
```

В сессии выполните `/reload-plugins`, `/preza:setup`, затем `/preza:preza` с задачей. Навыки остаются ручными: политика Codex `allow_implicit_invocation: false` сохранена; Claude использует описание и настоящий Skill tool при его наличии.

На устройствах с управляемым переносимым стеком используйте его post-install обработчик вместо прямой установки.

## Как это работает

Запуск — из папки предмета или компании: `/preza:preza` с задачей. preza сама раскладывает работу:

```
Макроэкономика/                  ← запуск отсюда
├── КУРС.md                      память предмета: требования к сдаче, имена файлов, ваши решения
├── Лекции/  Задания/  Материалы/      ← кладёте вы
└── Мое/                         серия: чья работа или про что (Иванов, Анна + Ольга, компания)
    ├── ПРОЕКТ.md                память серии: ФИО, группа, облик, сквозные числа
    └── ДЗ-4/                    папка задания — создаётся при старте
        ├── Тема_Фамилии.pptx    ← сдача
        ├── Тема_Фамилии_речь.docx
        ├── PLAN.md              карта работы
        └── Исходники/           1-вход · 2-материалы · 3-речь · 4-сборка · 5-проверка · 6-архив
```

1. **Старт.** preza находит предмет по `КУРС.md` (в первый раз спрашивает, предмет ли это, и создаёт каркас), читает память предмета и серии и прошлые работы серии.
2. **Вводная.** Одним пакетом спрашивает только то, чего нет ни в запросе, ни в памяти: серию и задание, ФИО и группу, нужна ли речь, длительность. Устойчивые ответы записывает в память — второй раз не спросит. Первое сообщение называет уровень проработки (Срочный, Обычный, Усиленный, Полный дизайн), папку задания и то, что взято из памяти.
3. **Маршрут.** Блоки по брифу (таблица «Маршрут») с независимым ревью по уровню; картинки — Codex `$imagegen` по правилу без генеративного слопа.
4. **Проверка.** Рендер PowerPoint и осмотр каждого слайда, детекторы пустот и служебных строк титула, сверка чисел; при речи — antiplagiat и Word.
5. **Итог.** Сдача в корне папки задания, абсолютные пути, ваши явные решения — в память. Вернётесь к работе — preza сначала заберёт ваши ручные правки Word.

Сессия без `/preza` узнаёт структуру из блока, который preza дописывает в `CLAUDE.md` предмета. Подробно — [layout.md](skills/preza/references/layout.md). Старые работы до 1.3.5 продолжаются на месте по старым путям.

## Начальное окружение

| Начальная сессия | Ведущий | Независимый рецензент | Генерация изображений |
|---|---|---|---|
| Codex | Codex | свежий субагент Codex | встроенный imagegen, иначе `codex exec` с `$imagegen` |
| Claude Code | Claude | свежий субагент Claude | `codex exec` с `$imagegen` |

Хост определяется по самой сессии и записывается в `runtime.json`; наличие двух CLI не задаёт ведущего. Скрипт распознаёт однозначный маркер `CODEX_THREAD_ID` / `CLAUDECODE`, при отсутствии или конфликте требует `--host`. Модели сохраняют настройки текущей среды; имена моделей одного клиента не подставляются в другой.

Файлы PPT Master ищутся в общей библиотеке `~/.agents/skills`, личных навыках клиентов и зарегистрированных пользовательских плагинах Claude. Codex читает их инструкцию по абсолютному пути; регистрация в Claude не означает доступность Skill tool в Codex. Копирование Markdown не переносит OAuth, MCP и нативные инструменты. Подробнее — [hosts.md](skills/preza/references/hosts.md).

## Зависимости

| Компонент | Назначение |
|---|---|
| Python 3.10+ | диагностика, сборка и проверка; Windows запускает с `-X utf8` |
| PPT Master и его `requirements.txt` | SVG → PPTX |
| doubt-driven-development (необязательно) | цикл независимого ревью; без него — промпт из hosts.md |
| Microsoft PowerPoint на Windows или macOS | эталонный рендер |
| Poppler: `pdftoppm`, `pdffonts` | PDF → PNG, шрифты |
| Codex CLI с входом и `$imagegen` | изображения, когда они включены в оформление |

PPT Master ставится из того же маркетплейса как `ppt-master@preza`: это форк [Inhibit0r/ppt-master](https://github.com/Inhibit0r/ppt-master) (ветка `preza`) — релизы [hugohe3/ppt-master](https://github.com/hugohe3/ppt-master) плюс указатели на правила deck-house-rules. Форк сам догоняет релизы upstream (GitHub Action с проверкой контракта preza), поэтому после обновления ppt-master ничего не правится вручную. Codex использует зарегистрированные файлы плагина Claude.

```sh
claude plugin install ppt-master@preza
python -X utf8 -m pip install --user -r <PPT_MASTER>/requirements.txt
```

На Mac используйте `python3`; ограничения установки Python-пакетов зависят от выбранной среды. Если раньше стоял `ppt-master@ppt-master`, удалите его (`claude plugin uninstall ppt-master@ppt-master`, `claude plugin marketplace remove ppt-master`) — `/preza:setup` подскажет. После обновления плагинов повторите setup.

Для отдельных блоков: Tavily/Firecrawl — внешние факты и поиск образцов; pandoc — материалы; frontend-slides — образцы; grill-me/grilling — идеи; доступный docx-навык, antiplagiat, avoid-ai-writing-russian и `aiw-ru` — речь. GitHub MCP нужен для репозиториев, но не является обязательным условием сборки презентации. Canva не требуется.

## Диагностика

```sh
python -X utf8 <PREZA>/skills/setup/scripts/doctor.py --host codex --offline --json
python -X utf8 <PREZA>/skills/setup/scripts/doctor.py --host claude --offline --json
```

Без `--offline` проверяются обновления зарегистрированных зависимостей. Код 0 — обязательные компоненты ядра обнаружены (рецензент — субагент сессии, отдельного входа не требует); 1 — не хватает обязательного; 2 — не определён хост или ошибка конфигурации. Обнаруженный MCP ещё требует реального вызова в активной сессии; обнаруженная инструкция imagegen ещё не доказывает наличие инструмента.

## Маршрут

| Источник / запрос | Блоки |
|---|---|
| Внешний доклад | Факты → История → Облик → Сборка → Проверка |
| Файлы пользователя | Материалы → История → Облик → Сборка → Проверка |
| Идея | Идеи → История → Облик → Сборка → Проверка |
| Образцы | Референсы → нужный источник содержания → основной маршрут |
| Анимация | Движение между Обликом и Сборкой; `/preza:animate` / `$preza:animate` для готового проекта |
| Речь | Word по финальным слайдам |

Нерешённые содержательные выборы согласуются с пользователем; уже заданный бриф и разрешённые действия сохраняются. Контрольный прогон записывает технические решения отдельно и не выдаёт их за пользовательское принятие рабочей презентации. Роли, ход и доказательства сохраняются в `PLAN.md`.

House rules одинаковы на обоих хостах: план изображений проходит ревью субагентом по уровню проработки; картинки создаёт Codex `$imagegen`; текст, графики и таблицы остаются редактируемыми; акценты делаются нативными фигурами без овальных свечений.

## Рендер и проверка

```sh
python -X utf8 <PREZA>/skills/preza/scripts/render_pptx.py <deck.pptx> <new-render-directory>
```

Windows: PowerPoint COM открывает отдельную копию с отключёнными макросами, экспортирует PDF, включает скрытые страницы только в копии и сохраняет исходный файл и уже открытые презентации. macOS: сохраняется прежний путь AppleScript через `render_pptx.sh`. Нужны локальный PowerPoint и Poppler; Linux не поддерживает эталонный рендер. Непустой каталог результата не перезаписывается.

После рендера осматриваются все страницы, сверяются шрифты и числа. Рендер показывает итоговые кадры, но не доказывает правильность воспроизведения анимации: её смотрят в PowerPoint. Проверки Windows и ролей покрыты тестами; живой прогон macOS выполняется на Mac.

## Проверки разработки

```sh
python -X utf8 -m unittest discover -s tests -v
python -X utf8 skills/setup/scripts/doctor.py --selftest
python -X utf8 skills/preza/scripts/check_deck.py --selftest
python -X utf8 skills/preza/scripts/check_svg.py --selftest
python -X utf8 skills/preza/scripts/check_speech.py --selftest
```

Разработка с клоном форка: `PREZA_PPT_MASTER=<клон>/skills/ppt-master claude --plugin-dir <клон preza> --plugin-dir <клон>/skills`.

Тесты проверяют исходное окружение, симметричные роли, приоритет локальных адаптаций, изоляцию MCP текущего клиента и защиту файлов рендера. Полный контрольный маршрут дополнительно требует реальных CLI, imagegen, PPT Master и PowerPoint.

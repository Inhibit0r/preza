# Ведущий, Orca и изображения

Ведущий — сессия, в которой владелец запустил preza. Сохраняй её модель и глубину. Для каждого самостоятельного поручения Codex объяви `$orchestration` и прочитай доступный навык оркестрации. Следуй справке установленной Orca. Профили в [worker-profiles.json](worker-profiles.json) задают **работников**. В `runtime.json` поле `worker_profiles` содержит модель и глубину для выбранного уровня. Выбор нового семейства моделей меняется в этом файле.

| Роль | Вход и выход |
|---|---|
| research | Один исследовательский вопрос, источники и разрешённый файл. Верни утверждения с единицами, периодами, URL или страницами и цитатами. |
| design | Тезис, данные, визуальный язык серии, соседние слайды. Верни схему композиции или конкретные редактируемые объекты в назначенном файле. Для сложной схемы проверь масштаб и порядок чтения до сборки. |
| image | Бриф каждого кадра из блока Облик. Верни путь к сгенерированному файлу, фактические размеры и предложенную обрезку. Когда у работника отсутствует инструмент ImageGen, верни промпт и композицию ведущему для генерации. |
| speech | Принятая ведущим раскадровка, лекции, тезисы и продолжительность. Верни единый текст по слайдам, пригодный для Word и заметок. |
| critic | Только артефакт, проверяемые требования, нужные PNG и принятый референс. Свежий контекст без объяснений автора. Верни по страницам вывод, его визуальное основание, конкретные дефекты и вердикт. |

Перед первым назначением объяви $orchestration и подготовь отдельный UTF-8 файл с заданием. Из папки основного навыка запусти:

    <python> scripts/dispatch.py --level "Обычный" --role critic --title "Визуальная проверка колоды" --brief <файл>

Обёртка передаёт модели и глубину выбранной роли в orca orchestration worker-start. Первый вызов создаёт или присоединяет Run. Сохрани его ID из JSON и передай --run <ID> для следующих назначений. Отсутствующий результат сначала сверяй через Orca. Безусловный повтор может создать второго исполнителя.

Каждый бриф указывает рабочую папку, разрешённые входы и файл результата, критерий готовности и получателя. Работник отвечает через `worker_done` со своим Task/Dispatch и `--report-path`. В PLAN.md запиши ID, роль, запрошенные модель и глубину, доступные подтверждения исполнения, артефакт и итог. Изображения, текст и анализ фактов могут идти параллельно в разных файлах. Общие спецификации и окончательный PPTX собирает один ответственный. Сверяй события и результаты уже запущенного задания до повтора. Без Orca ведущий может вести независимую подготовку самостоятельно. Для обязательного независимого ревью сохрани статус ожидания и сообщи ограничение.

В режиме Усиленный и Полный дизайн ключевые дизайнерские задачи и критик получают max. Если профиль недоступен, зафиксируй реальный статус. Контрольное сравнение Astra high и xhigh — отдельный эксперимент по запросу владельца, не часть выпуска каждой колоды. В обычном запуске не переключай ведущего и не отправляй материалы другому провайдеру.

## Независимое ревью

Критик открывает итоговые полноразмерные PNG. Для каждого содержательного слайда называет вывод и показывает, где на экране находится доказательство. Для сравнения проверяет основания и масштаб, для процесса — переходы и развилки. Для продолжения серии сопоставляет рендер с конкретным принятым примером. На новой теме оценивает соответствие аудитории, аргументу и выбранному визуальному направлению. Прикладывает номер слайда, наблюдение и применимую правку. Существенная ошибка даёт REVISE. Закрой её на исправленном рендере до отметки APPROVED. Без открытого изображения визуальное ревью остается невыполненным.

## Картинки

Используй встроенный Codex ImageGen. Качество кадра проверяй по [правилам оформления](../../deck-house-rules/SKILL.md) и по фактическому рендеру в месте постановки. Храни промпт, путь и замечания в проекте. Если в этой сессии или у исполнителя нет инструмента, сначала проверь возможность у ведущего. Другой сервис или платный API-путь требует выбора владельца.

## Окружение

`runtime.py --host codex --level "<уровень>"` сообщает путь к закреплённому PPT Master, Python сборки, Orca, правилам и локальной памяти. Команды Python из блоков выполняй массивом `python` из runtime, сохраняя `-X utf8`. В PowerShell вызывай исполняемый файл и аргументы по отдельности. При возвращении к старой работе обнови runtime по её раскладке. Конфликт старых ролей с кодексным запуском зафиксируй в плане. На штатном пути сверь engine_revision с pinned_revision. Если они разошлись, восстанови закреплённую копию через setup до сборки. Для явно заданного PREZA_PPT_MASTER отметь выбранное исключение в PLAN.md. Для установки движка и окружений открой setup. Поиск использует разрешённые Tavily, Firecrawl и резерв Agent-Reach. При исчерпании квоты зафиксируй пробел и используй разрешённый резерв. Ключи и авторизацию меняет владелец.

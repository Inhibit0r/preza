# Память презентаций

Путь `memory_root` берётся из runtime. На устройстве с существующим preza-memory укажи его через PREZA_MEMORY или локальную ссылку на этот каталог. Переносимые инструкции и частная библиотека примеров хранятся раздельно.

При начале работы прочитай небольшой `presentation-index.md`, если он есть. Найди максимум несколько записей, подходящих по типу задачи (сравнение, диапазон, причинная связь, процесс, интеграция изображения) и области действия. Открывай только подходящие примеры. В прежней базе можно адресно искать по термину в `compiled/blocks/<блок>.md`. Сверяй давность и область правила с текущим заданием. Полные архивы сессий не подгружай на старте. На чистом устройстве отсутствие памяти не блокирует бриф.

Во время работы фиксируй конкретные правки в PLAN.md. После **явного** принятия владельцем сохрани полезное обобщение в локальной библиотеке. Для поиска уже на старте из папки основного навыка выполни `scripts/memory.py find "<понятия задачи>"` и затем открой только нужные заметки. Пустой результат ведёт к принятому примеру серии или обычному проектированию по брифу. Поиск читает только короткие заголовки отдельных Markdown-файлов и возвращает до шести совпадений. Если total больше, уточни слова или вид записи.

Для новой записи подай текст через stdin в `scripts/memory.py remember <ключ> --kind example --title "<приём>" --tag "<понятие>" --evidence "<принятая версия и решение владельца>"`. Добавь несколько --tag по необходимости. В тексте укажи трудность, исправление, границы применения, локальные пути к версиям или PNG. Для явно общего предпочтения используй --kind preference. Одновременные записи в разные заметки независимы, точный повтор пропускается, конфликт имени останавливает запись для явной сверки. Индекс служит короткой навигацией по корпусу, для обнаружения новой заметки переписывать его не требуется. Важное для всех запусков предпочтение пометь в presentation-index.md либо свяжи с действующим house rule при обслуживании плагина.


Общее предпочтение, которое пользователь явно распространил на все колоды, фиксируется сразу с областью «все» в локальной памяти. Для уже действующего требования дай ссылку на deck-house-rules вместо дубликата. Новое правило серии запиши в ПРОЕКТ.md и свяжи с её DESIGN.md или спецификацией. Разовая просьба остаётся в PLAN.md. Повтор в разных проектах — основание предложить владельцу обобщение. Внутренний APPROVED разрешает первый показ, принятие владельца фиксируется отдельно. Реальные имена, личные материалы, рендеры и библиотека примеров остаются на устройстве.

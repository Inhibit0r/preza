# Проверка

Объём — по уровню (таблица в SKILL.md); обязательный минимум — на любом уровне. Раунды нумеруй: `5-проверка/round<N>/`.

1. Рендер: `scripts/render_pptx.py <deck.pptx> 5-проверка/round<N>` — PNG 1280×720 и список встроенных шрифтов (должны быть заявленные). Открой полноразмерный PNG каждого слайда — контактный лист только для обзора — и отметь номера открытых в PLAN.md. Отдельно смотри пустоты внутри панелей и карточек (детектор считает их по геометрии PPTX и пустую часть панели не видит), подписи поверх картинок (контраст с самой яркой зоной под ними) и акцентные фигуры поверх текста; после снятия надписи на титуле титул осматривается заново. Движение в маршруте → проверочная чистая копия тем же шагом: `python3 scripts/clean_deck.py <показ.pptx> <svg_output> -o 5-проверка/round<N>/check_clean.pptx` и её рендер в `5-проверка/round<N>/clean`; детектор и номера раскадровки работают по ней, промежуточные кадры Morph проверяет шаг 5a. Затем `python3 scripts/check_deck.py <deck.pptx или check_clean.pptx> --render <рендер той же колоды> --accept <номера слайдов с пометкой «пустота» в раскадровке> --authors "<фамилии из ПРОЕКТ.md>"` (учебная сдача — ещё `--strict`; задание требует курс на титуле — `--allow-title`): пустоты, счётчики «NN/NN», служебные строки титула, фамилии авторов вне титула и стоп-фразы исправь до показа пользователю; первый и последний слайды детектор пустот пропускает; номера `--accept` — по раскадровке, то есть по чистой колоде без промежуточных кадров Morph. Колода на тему ИИ — `--allow '<регулярка темы>'`, чтобы не путать тему с пометками о генерации.
2. Числа, если есть реестр: `python3 2-материалы/data/check_numbers.py --pptx <deck> --report 5-проверка/round<N>/numbers.md`, с речью — ещё `--script 3-речь/script.md`. Результат — ноль ошибок. Реестр сверяет набор значений, а не связь категории со значением: отдельно сопоставь пары категорий и рядов нативного графика с источником, а встроенную Excel-книгу — с кэшем графика. Подписи и смысл чисел проверь по рендеру; невыполненную проверку укажи как ограничение.
3. visual-review (Обычный и выше) — рубрика ppt-master `references/visual-review.md` по рендеру PowerPoint. Стадию `workflows/stages/visual-review.md` целиком не запускай: она снимает PNG через Playwright из SVG до экспорта, а дефекты экспорта видны только в рендере PowerPoint. Порядок раздачи берётся из неё:
   - записи страниц: N-й PNG раунда — N-я страница `svg_output/` в порядке ppt-master, промежуточные слайды Morph тоже; число PNG и страниц не совпало — остановись. `page_role` — из §IX `design_spec.md`, `canvas` — `viewBox` страницы и размер PNG;
   - пачки по 3 страницы, у колоды больше 30 страниц — по 5: пачки идут параллельно, страницы внутри пачки — по очереди, поэтому время раунда задаёт размер пачки. При доступном и разрешённом делегировании все пачки запускаются параллельно, модель выбирается из текущего хоста; иначе хост проходит пачки последовательно с теми же отчётами. В задании — абсолютные пути к рубрике, `design_spec.md`, `spec_lock.md` и записи пачки; Style Review Focus, если в проекте есть `templates/design_spec.style.*.md`; по каждому слайду — строка раскадровки и строки отчёта чисел как дополнительный контекст: задача слайда и формулировки при числах;
   - одна итерация: разрешённые рубрикой атомарные правки — в `svg_output/` с копией в `.review/backup/`; остальное и находки по дополнительному контексту — `needs_human` с предложением правки. Отчёты — `.review/<page>.json`, решения по токенам бренда — `.review/brand_review.json`. Субагент возвращает только пути отчётов и сводку до 150 слов;
   - пачки раунда запиши в `PLAN.md` до раздачи и отмечай каждую по возвращении: после паузы или сжатия контекста раздаются только неотмеченные.
4. Сведение — `5-проверка/fixes_round<N>.md` из отчётов `.review/`. Срочный: `spec_lock.md` нет, `update_spec.py` и `finalize_svg` не запускаются — правки по разделу «Revision after delivery» профиля `quick-generate.md`, остальное ниже — для стандартного маршрута: применённые правки и `needs_human` — принято, отклонено, почему. `brand_review.json` и другие правки для всей колоды — одним решением: цвет или шрифт — `update_spec.py` ppt-master (до запуска сохрани копию `svg_output/` и `spec_lock.md`: своего отката у скрипта нет), остальное — по всем затронутым страницам.
5. Усиленный и Полный дизайн: аудит сводки — независимое ревью (правило в SKILL.md), `plan` — `5-проверка/fixes_round<N>.md` с путями к PNG раунда; после правок — финальное независимое ревью по последнему рендеру тем же способом, в новой сессии.
5a. **Движение** (в маршруте): рендер показа — итоговые кадры каждого слайда, включая промежуточные; рендер чистой версии — слайдов столько же, сколько страниц без буквы, кадры совпадают с соответствующими слайдами показа. Само движение рендер не видит: пользователь смотрит показ в режиме демонстрации; если доступен PowerPoint под Windows — видео через ppt-master `scripts/powerpoint_video.py`. Экспорт MP4 на Mac анимации объектов не проигрывает (Microsoft) и проверкой не служит.
6. ✅ Спорные правки — пользователю (без пользователя — решает хост, SKILL.md §3). Принятые правки страниц вносит один исполнитель по `5-проверка/fixes_round<N>.md` целиком: доступный субагент текущего хоста или сам хост при недоступном делегировании; в задании — путь к сводке, `spec_lock.md` (Срочный — без него) и правило ppt-master для вернувшегося проекта (см. [Сборку](build.md), шаг 6). Правки идут пачкой: все принятые находки раунда — один проход по страницам, затем один экспорт и один рендер; по одной находке не правь и не рендерь. Затем [Сборка](build.md) → новый раунд: его рендер и visual-review проверяют правки. Обычно хватает двух раундов.
7. ✅ Финал. Речь в маршруте → сначала [speech.md](speech.md), «Финал»: он переэкспортирует PPTX с заметками, поэтому затем новый рендер финальных файлов (показа и чистой версии, если она есть), осмотр и `check_deck.py` — и только потом итог.
   - сверка «пункт задания → где выполнен» в `PLAN.md`; число слайдов — по заданию, длительность речи — мягкая цель ([speech.md](speech.md), шаг 2);
   - учебная сдача преподавателю — `--strict` у `check_deck.py` и `check_speech.py`;
   - сдача — в корень папки задания под именами из [layout.md](../references/layout.md), «Имена»; в `PLAN.md` — пути сданных файлов и sha256 каждого сданного PPTX (`shasum -a 256`; с Движением — показа и, если её просили, чистой версии), снятый после всех правок, включая свойства файла: по нему при возврате видны правки пользователя (SKILL.md §3); свойства файлов (поле «Автор» — инструмент сборки) меняются только по отдельному «да» пользователя;
   - `scaffold.py check <папка задания>`; в память — явно обобщённые решения пользователя (layout.md, «Память»);
   - итог пользователю — абсолютные пути PPTX, Word и `PLAN.md`; «осмотрен каждый слайд» — только если открыты все PNG последнего рендера, а слайды, правленные после осмотра, названы.

Готово, когда последний рендер осмотрен целиком, сверка чисел даёт ноль ошибок, серьёзных открытых замечаний нет и пользователь принял финал; без пользователя — неразрешённые замечания вынесены в итог (SKILL.md §3), а итог отдан с пометкой «ждёт вашего просмотра».

# Движение

Анимация показа в нативном PPTX: переходы, Morph и появление объектов через ppt-master. Половина «План» идёт после [Облика](look.md) и до [Сборки](build.md): промежуточные слайды Morph — обычные страницы ppt-master, их рисуют вместе с остальными. Половина «Разметка» — внутри Сборки, после проверки качества ppt-master. Проверка движения — шаг «Движение» в [Проверке](verify.md).

## Правила движения

- **Цель.** Каждое движение называет одну цель: связность (объект продолжается между слайдами), снять скачок (содержимое иначе прыгнет), объяснение (раскрытие по шагам), восторг (только обложка и финал). Цели нет — слайд без движения, и это нормальный ответ.
- **Переходы.** Между связанными слайдами — Morph 0,8–1,2 с; на границе блоков — `fade` 0,5 с; остальные — `fade` ppt-master по умолчанию (0,4 с). Эффектные переходы (куб, вихрь, оригами, шторы, пламя и подобные) не используются.
- **Появление.** `entrance_fade`, `entrance_rise_up`, `entrance_ascend` или `entrance_faded_zoom`; 0,4–0,7 с; `decelerate` 0,7–1,0 и `accelerate` 0 — это ease-out: движение стартует сразу и мягко садится.
- **Каскад.** Запуск `after-previous`, шаг 80–120 мс, по пути чтения: надзаголовок → заголовок → главный визуал → подписи. Всё сразу не появляется.
- **По щелчку** (`on-click`) — только там, где раскрытие и есть смысл: шаги процесса, колонки «что было / что сделали».
- **Тишина.** Отскоки (`bounce_end`), вращения, вылеты из-за края экрана, траектории, построчное появление обычного текста и звук без просьбы пользователя не используются.
- **Плавность.** В Morph двигаются фигуры и картинки умеренного размера; на переход — одно крупное Morph-движение; размытые подложки стекла хранятся уменьшенными. Microsoft советует ограничивать сложные анимации, крупные прозрачности и большие картинки в движении.
- **Морф — два статичных слайда.** Действие задаётся разницей между ними: выезд из-за края, поворот, увеличение (наезд камеры), один широкий кадр с двумя сдвигами по `x` (панорама). Справочник приёмов — ppt-master `references/animations.md` §2.1 и §3.1.
- **Носитель** — объект, который живёт на соседних слайдах и пересаживается: надзаголовок блока, фото-герой, уходящий в шапку следующего слайда, ось прогресса. Носители ориентируют зрителя; один ключ морф-пары может тянуться через целый блок.
- **Промежуточный слайд** — страница с буквой после номера: `10b_bfire-pan.svg` встаёт сразу после `10_bfire.svg` (ppt-master сортирует страницы по числам в имени). Буква — единственный признак, по которому чистая версия его убирает; у смысловых страниц буквы после номера нет.

## План — после Облика

1. **Вводная.** Узнай, где будут показывать: Morph с принудительными парами играет в PowerPoint 365, 2019 и новее, на Mac — от 16.23; в старых версиях он вырождается в затухание. Отдельным вызовом AskUserQuestion спроси «Нужна чистая версия — без переходов, анимаций и промежуточных слайдов?» с вариантами «Да» / «Нет», без рекомендации.
   Готово, когда версия PowerPoint показа и ответ про чистую версию записаны в `PLAN.md`.
2. **Бриф движения** — в `PLAN.md`, раздел `## Движение`: таблица `| слайд | цель | переход | объекты по порядку | запуск | длительность |` по каждому слайду раскадровки, включая слайды без движения. Ниже — список морф-пар: ключ, слайд-источник, слайд-приёмник, что меняется между концами.
   Готово, когда строка есть у каждого слайда раскадровки и у каждой морф-пары названы оба конца.
3. **Промежуточные слайды** — в раскадровку строками с буквой (`10b`) и пометкой «промежуточный, Morph от 10»; их время входит в хронометраж. В `design_spec.md` ppt-master включи Custom Animations в §I и запиши совет по движению в поле `Motion suggestion` §IX каждого затронутого слайда — ppt-master привяжет пары на стадии customize-animations.
   Готово, когда каждый конец каждой морф-пары запланирован как страница ppt-master, а имя промежуточной страницы следует правилу буквы.
4. ✅ Покажи бриф пользователю.
   Готово, когда пользователь утвердил бриф или свою правку к нему.

## Разметка — внутри Сборки

5. **`animations.json`** — по стадии ppt-master `workflows/stages/customize-animations.md` и брифу: аудит групп, `animation_config.py list-groups`, переходы и строки появления с `accelerate`/`decelerate`, морф-пары в блоке `morph` слайда-приёмника.
   Готово, когда `python3 <папка ppt-master>/scripts/animation_config.py validate <проект ppt-master>` проходит.
6. **Показ** — обычный экспорт Сборки: `svg_to_pptx.py` сам читает `animations.json` и проверяет каждую морф-пару. Сохрани копию как `<тема>_показ.pptx` в папке проекта.
   Готово, когда экспорт прошёл без ошибок пар, а путь записан в `PLAN.md`.
7. **Чистая версия** (ответ «Да» на шаге 1): `python3 scripts/clean_deck.py <тема>_показ.pptx <проект ppt-master>/svg_output -o <тема>_чистая.pptx` — снимает переходы и анимации и убирает промежуточные слайды.
   Готово, когда скрипт отчитался, а слайдов в чистой версии столько же, сколько страниц без буквы.

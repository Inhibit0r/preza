# preza

Ведущий — текущая сессия с выбранными пользователем моделью и глубиной. Ведущий сам проектирует колоду, собирает редактируемый PowerPoint и организует внутреннюю проверку до первого показа.

## 0. Начальное окружение

Прочитай [раскладку](references/layout.md) и [порядок работы с исполнителями](references/hosts.md). Выполни `scripts/runtime.py --host codex` и `scripts/scaffold.py find <папка запуска>`. Для проекта PPT Master и Python используй пути из результата. Прочитай [правила оформления](../deck-house-rules/SKILL.md). Из [локальной памяти презентаций](references/memory.md) подними только применимые предпочтения и примеры.

## 1. Вводная

1. Начни с темы, физической папки запуска, действующих AGENTS.md, задания, `КУРС.md` / `БРЕНД.md`, `ПРОЕКТ.md` серии. Учитывай приложенные лекции до вопросов и раскадровки. Выдели требования преподавателя, понятия, примеры и акценты с указанием исходного файла и страницы или таймкода. Различай условия задания, позицию лектора и собственные выводы.
2. Сам выведи аудиторию, вопрос доклада и нужный слушателю результат. Папка «Работа» задаёт проектный контекст, в «Учебе» найди дисциплину. Уточнённая пользователем тема имеет приоритет. Когда лекций нет, сформулируй аргумент из темы, проектных материалов и проверенных внешних фактов. Для серии посмотри принятую колоду и её Word или заметки: как начинает докладчик, что объясняет устно, как связывает слайды.
3. Одним коротким пакетом уточни только недостающие параметры: длительность **или** число слайдов, уровень (§2), нужна ли речь в Word. Уровень, явно выбранный в запросе, не переспрашивай. Предложи варианты с краткой разницей и возможность своего ответа. Зафиксированное для серии предпочтение используй. Аудиторию и цель в анкету не выноси. Разбирай противоречие с владельцем только если оно существенно меняет результат и условия не дают ответа. Для работы «без меня» используй условия задания и прежней серии, иначе Обычный, длительность по объёму материала и только PPTX; назови принятые допущения. Речь по умолчанию единая, деление по выступающим — по прямой просьбе.
4. Для известной папки предмета или компании: `scaffold.py init <корень> --kind <subject|company> --host codex`, затем `work <корень> --series <серия> --task <задание>`. Для отдельной работы используй `work <папка>`. Для найденной прежней работы сохрани её раскладку. Запиши `runtime.py --host codex --level "<уровень>" --write <runtime.json>` в путь этой работы. Копию условия с адресом источника положи в `1-вход/task.md`.
5. Начни `PLAN.md` строкой «Уровень: …; слайдов: …; речь: да/нет; preza: …». Добавь тему, основания вывода об аудитории и цели, источники стиля, маршрут, пропущенные блоки, роли и критерии. Показывай промежуточные варианты по просьбе пользователя. По умолчанию рабочие решения принимает ведущий. На содержательную или правовую неопределённость, которую нельзя разрешить из источников, укажи отдельно.

## 2. Маршрут

| Уровень | Облик и сборка | Внутренняя проверка |
|---|---|---|
| Срочный | Quick Generate, одно направление. ImageGen точечно для ключевого кадра. Для заказанной речи распараллель независимый текст и иллюстрации после раскадровки. | Осмотри все PNG, проверь факты и файлы. Отдельный критик по явному запросу. |
| Обычный | Полный дизайн каждой страницы в одном выбранном направлении. Стандартный Generate, продуманный ImageGen на уровне всей колоды. | Свежий критик проверяет раскадровку, затем каждый содержательный слайд по рендерам до первой выдачи. |
| Усиленный | Сравни возможные решения ключевых схем и иллюстраций. Полная проработка как в Обычном. | До сборки отдельно проверь сложные схемы и план изображений. После исправлений — повторный рендер и независимая проверка исправленной версии. |
| Полный дизайн | Изучи референсы, разработай три авторских направления с эскизами ImageGen и развей выбранное по всей колоде. В серии соблюдай её визуальный язык. | Усиленный маршрут плюс независимый финальный визуальный критик. До трёх содержательных раундов, затем явно укажи оставшиеся расхождения. |

Блоки открывай по ходу работы. Четыре обязательных этапа — [история](blocks/story.md), [облик](blocks/look.md), [сборка](blocks/build.md), [проверка](blocks/verify.md). Для внешних утверждений и чисел — [факты](blocks/facts.md), для лекций и файлов — [материалы](blocks/materials.md), для замысла из идей владельца — [идеи](blocks/ideas.md), для референсов и Полного дизайна — [референсы](blocks/references.md). [Движение](blocks/motion.md) включай по запросу между Обликом и Сборкой. На Срочном доступны простые переходы и появления флагами Quick. [Речь](blocks/speech.md) включай, когда заказана.

## 3. Исполнение и первая выдача

По умолчанию используй русский и формат 16:9, если задание, шаблон или серия не требуют другого. Зафиксируй за каждым блоком ответственного, вход, выход и критерий. Для работников объяви `$orchestration` и следуй [протоколу Orca](references/hosts.md). Решения по вердиктам, пути версий и следующий незакрытый шаг записывай в PLAN.md. После паузы восстановись по нему и runtime.json. Ведущий отвечает за целостность всей работы.

Минимум для любой выдачи: проверка кегля и плотности SVG до экспорта, сверка чисел и источников, экспорт редактируемого PPTX, рендер финальных файлов в PowerPoint и осмотр каждого слайда в полном размере. Выполни `check_deck.py` с дословными надписями обложки из брифа (`--cover-text`) и фамилиями авторов при их наличии, `check_numbers.py` при реестре и `scaffold.py check` для текущей раскладки. Для речи выполни её финальный блок с Word, заметками и antiplagiat. Начиная с Обычного перед выдачей обязательно получить привязанный к финальным файлам отчёт по [визуальной композиции](references/visual-composition.md). Формальные проверки дополняются предметной оценкой: критик должен суметь прочитать вывод и показать его основание на слайде.

Исправляй существенные визуальные замечания внутри процесса. Первый показ — проверенная версия, пути сдачи и существенные ограничения. Если обязательная проверка сорвалась, отметь открытый этап. Решение критика и принятие владельцем — отдельные события. После отклика владельца примени [правила памяти](references/memory.md).

**Возврат к сданной работе** — любой новый запрос по работе, у которой в PLAN.md записаны сданные файлы. До любой правки:
1. Word: `python3 scripts/check_speech.py 3-речь/script.delivered.md --slides <N> --docx <сданный Word>`; разделы, которые не совпали, — правки пользователя: перенеси их дословно в `3-речь/script.md`.
2. PPTX: сравни sha256 каждого сданного PPTX (`shasum -a 256`; с Движением и чистой версией их два) с записанным в PLAN.md при сдаче. Отличается — пользователь правил его в PowerPoint: до переэкспорта из SVG спроси, перенести правки в SVG или дорабатывать сам PPTX; без пользователя — дорабатывай сам PPTX: переэкспорт затёр бы его правки.
3. Файл, открытый в Office (рядом `~$…`), не перезаписывай.

Старая работа без снимка: расхождения Word и её речи — файла `script.md` в корне старой работы (layout.md, «Пути»; `check_speech.py <этот файл> --slides <N> --docx …`) — покажи пользователю одним вопросом; sha256 у старой работы не записан — тем же вопросом спроси, правил ли он PPTX (без пользователя — дорабатывай сам PPTX).

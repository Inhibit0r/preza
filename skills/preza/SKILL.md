# preza

Презентация собирается по **маршруту** — набору блоков под конкретную задачу. Порядок блоков постоянный, состав меняется: факты, материалы, идеи, референсы и речь включаются по условию; история, облик, сборка и проверка есть всегда. Пути `scripts/…` и `blocks/…` — от папки этого навыка.

Хост — Claude Code с плагином ppt-master. Роли:
- хост — вводная, маршрут, раскадровка, текст, SVG, сведение правок;
- Codex (сильнейшая доступная модель, reasoning high) — независимый критик через `claudex-loop` и художник через `$imagegen`;
- субагенты на дешёвой модели (например, `sonnet`) — параллельная работа: исследование по осям, проверка по слайдам;
- ppt-master — сборка SVG в нативный PPTX.

## 1. Вводная

Из запроса возьми: тему и цель, аудиторию, длительность, формат (по умолчанию PPTX 16:9), источник содержания, облик, важность, папку проекта.

Недостающее, что меняет маршрут, спроси одним вызовом AskUserQuestion, рекомендуемый вариант первым; пункты, на которые запрос уже отвечает, пропускай:
- длительность или число слайдов;
- источник содержания (можно несколько): открытые источники / мои материалы / мои идеи / образцовые презентации;
- облик: свободный, из смысла темы / фирменный стиль / сначала референсы.

Вопрос «Нужна речь к презентации в Word?» («Да» / «Нет», без рекомендации) задавай всегда, если запрос сам не сказал о речи.

Важность читай по словам запроса: «черновик», «набросок» → черновик; «важно», «руководству», «защита», «экзамен» → важная; иначе — обычная. «По образу и подобию» образцов означает перенос приёмов (см. «Уникальность»).

Умолчания назови в том же сообщении, что и вопросы (или вместе с маршрутом, если вопросов нет): русский язык; PPTX 16:9; аудитория — предположение по контексту; папка проекта — новая подпапка текущей папки с названием по теме; слайд источников, если есть внешние факты (данные из файлов пользователя подписываются на своём слайде).

Готово, когда каждый пункт взят из запроса, из ответа или назван как умолчание.

## 2. Маршрут

| Блок | Включай, когда | Результат | Остановка | Файл |
|---|---|---|---|---|
| Факты | нужны внешние проверяемые числа и утверждения | реестр чисел с источниками | — | [blocks/facts.md](blocks/facts.md) |
| Материалы | пользователь дал файлы, заметки, записи | выжимка с привязкой к файлам | — | [blocks/materials.md](blocks/materials.md) |
| Идеи | содержание — мысли пользователя | тезис и опорные мысли | подтверждение тезиса | [blocks/ideas.md](blocks/ideas.md) |
| Референсы | есть образцовые презентации или нужно собрать референсы | бриф приёмов | бриф | [blocks/references.md](blocks/references.md) |
| История | всегда | раскадровка; ревью плана Codex по важности | раскадровка и черновик речи | [blocks/story.md](blocks/story.md) |
| Облик | всегда | направление, спецификация, картинки | направление | [blocks/look.md](blocks/look.md) |
| Сборка | всегда | нативный PPTX | — | [blocks/build.md](blocks/build.md) |
| Проверка | всегда | проверенный PPTX | спорные правки и финал | [blocks/verify.md](blocks/verify.md) |
| Речь | ответ «да» про речь | черновик — в Истории, Word — после Проверки | вместе с раскадровкой и финалом | [blocks/speech.md](blocks/speech.md) |

Файл блока читай, когда до него дошла очередь.

Стартовые наборы задают только состав блоков:

| Задача | Блоки |
|---|---|
| Аналитический доклад | Факты → История → Облик → Сборка → Проверка |
| По идеям | Идеи → История → Облик → Сборка → Проверка |
| По материалам | Материалы (+ Факты на пробелы) → История → Облик → Сборка → Проверка |
| По образцам | Референсы → блок содержания по ситуации → История → Облик → Сборка → Проверка |

Важность задаёт глубину ревью:

| Важность | Ревью плана Codex | Проверка |
|---|---|---|
| черновик | нет | рендер и осмотр хостом |
| обычная | один проход | + visual-review по слайдам, сверка чисел |
| важная | `claudex-loop`, до трёх раундов | + аудит правок и финальная инспекция Codex |

Покажи маршрут таблицей «№ | блок | навыки и инструменты | что получится | остановка» и одной строкой — пропущенные блоки с причиной. Навыки блока — по таблице из раздела «Навыки — загружать и объявлять явно». Готово, когда пользователь утвердил маршрут или свою правку к нему.

## 3. Выполнение

Создай папку проекта и `PLAN.md`: вводная, маршрут, решения с причинами, ход работы. Обновляй его после каждого блока — по нему работа продолжается после паузы или сжатия контекста.

Проходи блоки по порядку; каждый заканчивается своим критерием готовности. На остановках из таблицы блоков жди решения пользователя, между ними работай без повторных «ок».

## Навыки — загружать и объявлять явно

Пользователь видит подключённое в строке состояния (claude-hud: строки Skills, MCPs, Agents). Она считает только настоящие вызовы инструментов, поэтому навык, прочитанный как файл, для пользователя не объявлен.

- В начале блока загрузи его навыки инструментом `Skill` и тем же сообщением напиши строку `▎ Подключаю: <навык> — зачем`. Чтение `SKILL.md` через Read или Bash (`cat`) загрузкой не считается. В Codex инструмента `Skill` нет: открой `SKILL.md` навыка и объяви той же строкой.
- Навык загружается один раз за сессию; блок, которому он нужен снова, ссылается на уже загруженный.

| Блок | Загрузить через `Skill` | Остальное (видно в HUD как) |
|---|---|---|
| Вводная, до плана оформления | `preza:deck-house-rules` | — |
| Факты, Референсы | `agent-reach` — только резерв после Tavily и Firecrawl | MCP `tavily`, `firecrawl` (MCPs); субагенты по осям (Agents) |
| История — ревью Codex; Облик — картинки; Проверка — аудит (важная) | `claudex-loop` | Codex CLI (Bash) |
| Облик, Сборка, Проверка — visual-review | `ppt-master:ppt-master` | субагенты на слайд (Agents) |
| Материалы | — (`to-md:convert` запускается только вручную) | pandoc (Bash) |
| Идеи | `grill-me` или `grilling` | — |
| Речь | `antiplagiat`, `avoid-ai-writing-russian`, `document-skills:docx` | детектор `aiw-ru` (Bash) |

- Файлы блоков (`blocks/*.md`) и скрипты preza — не навыки: они читаются и запускаются как файлы и в строке Skills не появляются.
- Навык только для ручного запуска (`disable-model-invocation: true`) не вызывай и не приписывай себе; нужен он — покажи строку `▎ Ручной сценарий: <навык> — зачем. Запуск: /<навык>`.
- Сам `preza:preza` тоже ручной. Команда пользователя попадает в журнал как его сообщение, и claude-hud её не показывает — повторно не вызывай.
- Объявляй только то, что действительно загружено или вызвано: упоминание навыка в маршруте — не загрузка.

## Уникальность

Каждая презентация — самостоятельная работа: облик, раскадровка и метафора выводятся из смысла её темы и материала. Совпадать с прошлыми работами и референсами допустимо приёмами — так же понимается и просьба сделать «по образу и подобию». Проверка: положи слайд рядом с источником приёма — глаз видит другую работу.

Шаблоны ppt-master `templates/styles` и `templates/layouts` — библиотека приёмов и референсов. Шаблоны `templates/charts` и `templates/tables` — рабочий инструмент для нативных графиков и таблиц. Фоны и иллюстрации создаёт Codex `$imagegen`.

Для той же компании переносятся фирменные константы (палитра, шрифты) из её прошлой спецификации; композиция и метафора новые.

## В любом маршруте

- Картинки и оформление — по [deck-house-rules](../deck-house-rules/SKILL.md); загрузи его через `Skill` (`preza:deck-house-rules`) до плана картинок.
- Поиск и извлечение в интернете — Tavily; при ошибке, лимите или слабом результате — Firecrawl; Agent-Reach — резерв после обоих. Российские сайты с сертификатом Минцифры — Firecrawl с `skipTlsVerification: true`, при 403 — чтение страницы напрямую.
- Истина — рендер PowerPoint: `scripts/render_pptx.sh <deck.pptx> <папка>`; осматривай каждый слайд.
- Каждое число на слайде и в речи — из источника или из материалов пользователя.
- Ограничения, которые назвал пользователь, записывай в `PLAN.md` сразу и держи во всех блоках.

# Окружение preza

Сначала найди корень этого навыка. Команды ниже привязаны к его scripts/. Определи профиль `codex`, `claude` или `manual` по [таблице хостов](../preza/references/hosts.md). Для отдельной установки задай `PREZA_DATA_DIR` абсолютным путём и передай его всем командам preza. Действия с установкой выполняй в согласованном объёме. На машине с переносимым стеком для установки самого плагина используй штатный install.py. Зависимости сборки живут отдельно от каталога навыков.

1. Для подготовки движка запускай `python -B scripts/prepare_engine.py --checkout-only`. Он получает закреплённый Git commit форка, размещает его в пользовательской папке и сохраняет существующие изменения при конфликте. Для полностью подготовленного окружения запусти тот же скрипт без флага каждым нужным интерпретатором. На Mac основные варианты — Homebrew Python 3.14 и Framework Python 3.12. Каждый получает свою venv с requirements движка и python-docx. Путь к готовому Python печатается в конце. При повторном запуске используется тот же checkout и venv.
2. Выполни `<venv-python> -X utf8 scripts/doctor.py --host <хост> --offline --json`. Смотри отдельно ядро, компоненты блоков и выбранные пути. Ревизия движка определена в основном runtime.py. Явное `PREZA_PPT_MASTER` позволяет выбрать другую копию при разработке. В отчёте зафиксируй использование override. Для сведений о состоянии upstream вызывай doctor без offline, когда это входит в задачу.
3. Проверь доступные инструменты текущего клиента для выбранных блоков. Orca и встроенный ImageGen относятся к штатному профилю Codex. Другой хост использует свой доступный инструмент и свой способ независимой проверки. Наличие инструмента подтверждает вызов, назначение работника — квитанция или ссылка на фактический запуск. Изображение, экспорт и прочие функциональные результаты проверяй при заказанном прогоне. Для Word и текстовой проверки отдельно нужны доступный docx-навык, antiplagiat и aiw-ru. При ошибках поиска используй уже разрешённые источники. Учётные данные меняет владелец.
4. Локальная память доступна по `memory_root` из runtime. Подключение уже имеющегося корпуса — через PREZA_MEMORY или локальный указатель. Обзор и хранение описаны в [памяти](../preza/references/memory.md).
